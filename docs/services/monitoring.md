# Monitoring

Prometheus, Grafana and Alertmanager for both clusters, designed in [ADR 0010](../decisions/0010-monitoring.md): one Prometheus per cluster, one Grafana (on the Lenovo) with a data source for each. Installed by Flux as the `kube-prometheus-stack` chart.

## What runs where

| | Lenovo (`extreme`) | Mac mini (`zion`, later `mini`) |
|---|---|---|
| Stage | 1 (stack running, nothing sensitive, no outside access) | not started: after the Immich cutover |
| Prometheus | 15 days of data, 25Gi local-path volume | planned: small, 7 days |
| Grafana | yes (stateless) | no: queried from the Lenovo's Grafana |
| Alertmanager | yes; Telegram arrives in stage 2 | no |
| Exporters | node-exporter, kube-state-metrics | the same, plus `node_exporter` on the macOS host |

Manifests: `infrastructure/base/monitoring/` (namespace, chart repository), `infrastructure/extreme/monitoring/` (HelmRelease and values), `clusters/extreme/monitoring.yaml` (the Flux Kustomization). Prometheus data is disposable and is not backed up (ADR 0010); Grafana keeps no state of its own.

## Open it (stage 1: port-forward, from a machine with a kubeconfig for `extreme`)

```sh
kubectl --context extreme -n monitoring port-forward svc/kube-prometheus-stack-grafana 3000:80
# open http://localhost:3000, user admin
kubectl --context extreme -n monitoring get secret kube-prometheus-stack-grafana -o jsonpath='{.data.admin-password}' | base64 -d; echo
```
The password is generated by the chart into a Secret; stage 2 replaces it with a SOPS secret. Prometheus is `svc/kube-prometheus-stack-prometheus` on port 9090 and Alertmanager `svc/kube-prometheus-stack-alertmanager` on 9093.

## Verify it works

```sh
flux get kustomization monitoring --context extreme               # READY True
kubectl --context extreme -n monitoring get helmrelease           # READY True
kubectl --context extreme -n monitoring get pods                  # all Running
```
In Prometheus, Status, then Targets: everything `UP` except nothing for etcd, scheduler, controller manager and kube-proxy (disabled on purpose: k3s runs them inside one process). In Grafana, the dashboard "Node Exporter / Nodes" shows the Lenovo's CPU, memory, disk and network.

## Stages (ADR 0010)

1. Stack on the Lenovo, checked through a port-forward (this document).
2. SOPS secrets (Grafana admin, Telegram bot token), Grafana reachable on the tailnet as `grafana-ubuntu-extreme`, alert rules: disk over 80%, link speed below 1000 Mb/s, device-plugin DaemonSet unavailable, Flux not ready, crash loops.
3. Immich metrics and the backup jobs (the sync scripts write a last-success timestamp for node_exporter's textfile collector; alert after about 26 hours); dashboards kept in Git.
4. The mini after the Immich cutover, the overview dashboard over both data sources, the dead-man's switch.
5. Later: a read-only Telegram bot, logs (Loki), file browsing.
